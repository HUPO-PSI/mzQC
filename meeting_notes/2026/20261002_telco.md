Repository QC

* The HUPO bioinformatics hub session on making public data reusable highlighted that both metadata (SDRF) and QC information are needed to select high-quality datasets (e.g., for training machine learning models).
* There is excitement about making QC information directly available in PRIDE.
* Yasset will reach out in the near future to get this effort started.

mzQC specification version 1.1

* The QC metric organization will go into the 1.1 specification update, together with technical changes:
   * [Issue 262](https://github.com/HUPO-PSI/mzQC/issues/262): upgrade the JSON schema, include software settings, and the matrix type.
   * Clarification of NaN versus null to ensure full JSON compliance.
* These changes are relatively small and should be backwards compatible. Adding software settings does not invalidate existing files, and few if any existing files use NaN or infinity.
* The new SDRF-style metadata templates (immunopeptidomics, metabolomics) are nearing production, as presented at HUPO. Nils will follow up on this.

Integration with other formats and tools

* mzPeak: Patrick's group in Tübingen is working on it. It allows embedding other information, so mzQC could be embedded in the mzPeak file, giving a single file instead of separate SDRF, mzQC, and mzML files. Wout agrees we should keep an eye on this.
* OpenMS: DI Auditor, TD Auditor, and probably a DD Auditor are likely to become OpenMS tools over the next year. A quick test porting DI Auditor to C++ went well. Timo handles the porting, and the tools will make fuller use of the PSI-MS CV.
